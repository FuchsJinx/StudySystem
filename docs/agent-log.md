## 2026-11-10 — Автономный агент / DeepSeek Harness

**Задача:** Аудит репозитория, реализация модулей 1–11, тесты, Docker, Git-история.
**Промпт / скилл:** полное ТЗ пользователя + `AGENTS.md`, `docs/spec/`, `docs/qa/`.
**Результат:** этап 1 (auth, профили, подтверждение) и этап 2 (АР, списание) — реализованы; 34 backend + 13 frontend тестов зелёные, Playwright-сценарий создания задачи → сдачи → приёмки пройден.

**Ошибка агента:** миграция V3 падала на `ALTER TYPE` для `membership_status` — default-значение ссылалось на удаляемый enum-тип; для `award_feed_items.currency` CHECK-ограничение сравнивало varchar с enum.
**Как обнаружили:** запуск приложения + Flyway; прогон миграций в scratch-БД через psql.
**Исправление:** перед сменой типа сброшены DEFAULT, удалено CHECK-ограничение, после конвертации значения и ограничения восстановлены (VARCHAR + CHECK).

**Ошибка агента:** Vite watcher падал с EBUSY на временных каталогах `.tmpdir`, создаваемых инструментом записи файлов.
**Как обнаружили:** падение dev-сервера при сохранении страницы.
**Исправление:** `server.watch.ignored` для `**/.*.tmpdir/**`, `**/*.tmp`; перезапуск Vite.

**Ошибка агента:** интеграционный тест ожидал `debitedStudents == 0` после сдачи одного студента, но в группе оставался второй просроченный студент.
**Как обнаружили:** `mvn -Dtest=RatingIntegrationTest test`.
**Исправление:** проверка перенесена на АР конкретного студента, а не на глобальный счётчик тика.

**Что сработало:** интеграционные тесты на реальном PostgreSQL (`@SpringBootTest` + Flyway), прямой вызов тика списания, pessimistic lock на submission/student; Playwright с системным Edge (`channel: msedge`) без скачивания браузера.

**Ошибка агента:** проверка бюджета была реализована как «инкремент → проверка лимита → откат транзакции»; в интеграционном тесте, где все HTTP-запросы идут в одной тестовой транзакции, превышение не откатывалось до конца теста, и `spent` оставался 75 при лимите 60.
**Как обнаружили:** `mvn -Dtest=ActivityIntegrationTest test`, assertion `$.spent expected 50 but was 75`.
**Исправление:** бюджет изменён на условный PostgreSQL upsert (`WHERE budget_spends.amount + EXCLUDED.amount <= limit`), который не меняет строку при превышении; откат больше не нужен. Это также корректнее для production.

**Что сработало (модуль 3):** отдельный `BudgetStore` на `JdbcTemplate` с атомарным upsert; проверка бюджета до создания награды; E2E-сценарий SOCIAL → запись → награда 50 % → публичная лента/профиль.

**Ошибка агента:** интеграционные тесты выполнялись в той же БД `unirate`, что и демо/E2E-данные. После E2E абсолютные суммы ledger и бюджета в тестах перестали совпадать с ожиданиями (BOA 100 вместо 50, `spent 75`).
**Как обнаружили:** полный `mvn test` после E2E-прогонов.
**Исправление:** тестовый профиль переведён на отдельную БД `unirate_test`; CI создаёт её через PostgreSQL service; в README добавлена команда создания. E2E больше не влияет на интеграционные assertions.

**Ошибка агента:** тест RBAC «студент не может создать опрос» отправлял пустое тело; bean validation срабатывала раньше `@PreAuthorize`, и тест получал 400 вместо 403.
**Как обнаружили:** `mvn -Dtest=PollIntegrationTest test`.
**Исправление:** для проверки роли отправляется валидное тело опроса; 403 проверяется корректно.

**Ошибка агента:** импорт студентов выполняется в `REQUIRES_NEW` (частичный успех), поэтому тестовые строки коммитились вне тестовой транзакции и накапливались в БД. Кроме того, при сбое импорта cleanup мог упасть на `orElseThrow`.
**Как обнаружили:** повторные прогоны `AdminIntegrationTest`, рост числа студентов.
**Исправление:** импортные тесты вынесены из общей транзакции (`NOT_SUPPORTED`) и получили безопасный `finally`-cleanup; CI использует чистую БД.

**Ошибка агента:** при первом запуске Docker Compose backend падал с `ConverterNotFoundException` на `unirate.demo-seed`: env `UNIRATE_DEMO_SEED=true` конфликтовал с вложенным объектом настроек.
**Как обнаружили:** `docker compose up -d --build`, лог `APPLICATION FAILED TO START`.
**Исправление:** переменная переименована в `UNIRATE_DEMO_SEED_ENABLED` (relaxed binding для вложенного свойства); стек поднялся, seeder отработал.

**Что сработало (модули 5–11):**
- ключевые поля `hasVoted/results/voters` вычисляются на backend, UI не может обойти анонимность;
- deadline-напоминания идемпотентны через `deadline_reminders` + unique constraint;
- админ-импорт поддерживает CSV и XLSX (Apache POI), отчёт по строкам;
- уведомления отправляются после commit, внешние каналы не ломают бизнес-транзакцию;
- аналитика восстанавливает историю АР из ledger «назад от текущего значения», без отдельного снапшота;
- AI честно помечает `provider=demo` при отсутствии ключа, а ошибка настроенного LLM даёт 503.

**Финальная проверка:** `mvn test` — 88 passed; `npm test` — 13 passed; `npm run build` — OK; Playwright против `docker compose` — 8 passed; worker списывает 20 АР за тик, останавливается на cost; письма в Mailhog доставляются; демо-данные создаются `DemoDataSeeder`.

**Что сработало в процессе:** интеграционные тесты на реальном PostgreSQL, отдельная тестовая БД, Playwright с системным Edge локально и Chromium в CI, Docker-сборка с `npm ci` и `.dockerignore`, идемпотентный demo seeder с относительными датами.
